# 示例（虚构）/ Example (fictional)：周报漏掉必核章节

> This case was invented to show the format. It is not a real event. The team, report, and figures are fictional.

- 日期 / Date: 2026-11-10
- 记录人 / Recorded by: 运营负责人（示例角色）/ operations lead (example role)
- 状态 / Status: 已验收，已写入规范 / verified and written into norms

## 止损 / Containment

- 止损完成时间 / Containment completed at: 2026-11-11 10:15（补正版发出）。

## 问题陈述 / Problem statement

2026-11-11 09:20，运营负责人在处理退货单 R-4517 时对照周报，发现《2026 年第 45 周销售周报》缺少写作指南中列为必有的「退货核对」一节。订单系统该周退货合计为 12,400，报告未列此数，净销售因此少扣 12,400。报告于 2026-11-10 18:06 由作者直接发出。写作指南第 4 条写明：每周必须包含退货核对，即便本周退货为 0，也要写明「本周退货 0」。

## 三条腿 / Three legs

### A. 发生 / Occurrence

| 问次 / Why | 回答 / Answer | 证据 / Evidence | 事实或假设 / Fact or hypothesis |
| --- | --- | --- | --- |
| 1 | 第 45 周的文件里本来就没有「退货核对」这一节，不是发出时被删掉的。 | 发出稿与作者工作目录中的定稿一致，目录中无该节标题；发送记录 18:06 附件哈希与定稿相同。 | 事实 / Fact |
| 2 | 作者是复制第 44 周的文件再改数字。第 44 周的文件里这一节已经被去掉了。 | 第 45 周文件的创建记录为「复制自 第44周销售周报」；第 44 周文件同样没有「退货核对」标题。 | 事实 / Fact |
| 3 | 第 44 周退货为 0，当时作者把空的一节删掉，想让报告更短。这一删，成了下一周的底稿。 | 第 44 周正文有一句「本周无退货」，但没有独立章节；作者在第 44 周编辑说明里写了「空节已删」。 | 事实 / Fact |
| 4 | 周报没有锁定的母版。任何人都可以从最近一份文件接着改，被删掉的章节会跟着走。 | 团队目录里没有只读母版；写作指南只给出章节名称，没有不可删的模板文件。 | 事实 / Fact |

- 根因 / Root cause: 周报从上一份文件复制，又没有锁定母版，一次删节会变成后续各周的默认结构。
- 倒读检查 / Backward read: 没有锁定母版，所以第 44 周删掉的节进入第 45 周底稿；所以发出稿没有「退货核对」；所以 12,400 没有入报。链子接得上。

### B. 发现 / Detection

| 问次 / Why | 回答 / Answer | 证据 / Evidence | 事实或假设 / Fact or hypothesis |
| --- | --- | --- | --- |
| 1 | 报告发出前没有第二人看，也没有检查必有章节是否还在。 | 发送记录显示作者于 18:06 直接发出；当天没有复核意见或检查输出。 | 事实 / Fact |
| 2 | 流程要求周一 18:00 前发出，但没有安排复核时间，也没有「缺节就不可发出」的门槛。 | 《周报安排》只写了截止时间；没有复核人、复核时点，也没有发出前检查。 | 事实 / Fact |
| 3 | 作者的自查只是「数字看上去是否合理」，不是按必有标题逐项勾选。 | 写作指南第 7 条是「发出前通读一遍」；没有必有章节清单，也没有对照这份清单的检查。 | 事实 / Fact |

- 根因 / Root cause: 发出前没有必有章节检查，复核只靠作者通读，缺节不会被卡住。
- 倒读检查 / Backward read: 没有缺节即卡住的检查，所以缺少「退货核对」的稿也能在 18:06 发出；所以第一道发现要等到第二天对单。链子接得上。

### C. 体系 / System

| 问次 / Why | 回答 / Answer | 证据 / Evidence | 事实或假设 / Fact or hypothesis |
| --- | --- | --- | --- |
| 1 | 「必须包含退货核对」只写在写作指南的段落里，没有变成发出条件。 | 写作指南第 4 条有该要求；《周报安排》的发出步骤中没有「必有章节检查通过」。 | 事实 / Fact |
| 2 | 当初写流程时，只写了文风和章节建议，没有做母版，也没有做出发出前的检查。 | 写作指南引言写的是「供撰写时参考」；仓库里没有模板文件，也没有发出前检查的记录。 | 事实 / Fact |
| 3 | 必有章节被当成写作建议，而不是能不能发出的条件。 | 指南用词是「应包含」「参考」；安排表用词是「按时发出」。两者都没有「缺节不得发出」。 | 事实 / Fact |

- 根因 / Root cause: 必有章节只存在于说明文字里，既没有锁定母版，也没有发出前必须通过的检查。
- 倒读检查 / Backward read: 要求只写在说明里，所以复制旧文件、删节、直接发出都不会被挡住；所以缺节周报能送到管理层。链子接得上。

## 停问核对 / Stop-rule check

- 三条腿都追到了模板、发出前检查和规范写法，没有停在「作者忘了」。
- 若只给第 45 周补上这一节，下一周若再复制旧文件，同类缺失仍会再发生，所以不能停在这一份补正。

## 对策 / Countermeasures

| 腿 / Leg | 针对的根因 / Root cause addressed | 对策 / Countermeasure | 防止或拦住 / Prevent or catch |
| --- | --- | --- | --- |
| A 发生 / Occurrence | 复制上一份文件，删节会遗传 | 改用锁定母版。必有章节（含「退货核对」）固定存在；本周为 0 时写「本周退货 0」，不能删节。新一周从母版生成，不再复制上一周的文件。 | 防止 / Prevent |
| B 发现 / Detection | 发出前无缺节检查 | 发出前增加检查：对照必有标题清单读取稿件，缺任一标题则发出被卡住。可由脚本来做，也可由 AI 步骤按同一份清单来做，但必须在发出前卡住，而不是事后提醒。 | 拦住 / Catch |
| C 体系 / System | 必有章节只写在说明里 | 更新《周报安排》：只准使用母版；发出前必须通过必有章节检查；写作指南第 4 条从「应包含」改为发出条件。 | 防止 + 写入规范 / Prevent and write into norms |

| 字段 / Field | 内容 / Content |
| --- | --- |
| 错误类型 / Error class | 定期报告缺了必有章节，或从上一份文件复制以致删节被遗传。 |

## 摘要 / Summary

根因不是「这一周忘了写退货」，而是：周报从上一份文件复制，必有章节只写在说明里，发出前没有缺节就卡住的检查。第 44 周为了缩短篇幅删掉空节，第 45 周就把 12,400 的退货漏出了报告。现在新一周必须从锁定母版生成，发出前对照必有标题，缺节就卡住，并把这写成发出条件。用一份缺节副本验收，检查确实能拦住。月度库存汇报和到书清单已按同样方式改完。
